## 一、角色与权限

| 界面名 | 标识 | 等级 | 权限 | 缴费对象 |
|--------|------|------|------|---------|
| 普通成员 | `MEMBER` | 0 | 只读（含自己的缴费/任务） | ✅ 交班费 |
| 访客 | `GUEST` | 0 | 只读**受限范围**（班主任逐项指定） | ✅ |
| 生活委员 | `ADMIN` | 1 | 运营 | ✅ 交班费 |
| 班长 | `MONITOR` | 2 | 运营 | ✅ 交班费 |
| 班主任 | `TEACHER` | 3 | 运营 + 本班管理 | ❌ 不参与 |
| 院长 | `DEAN` | 4 | **系统管理员**（学院层全权） | ❌ 不参与 |

### 规则

- **运营权限三者一致**（班主任之下的 ADMIN/MONITOR/TEACHER 记账/作废/小票/成员管理/批次/公告同权），差别在两处：
  - **等级护栏**：不能创建或操作比自己等级高的账号（`院长 > 班主任 > 班长 > 生活委员 > 成员`），
    判定一律看 `ROLE_LEVEL` 等级，不写角色名；
  - **管辖范围**：班主任管自己的班；院长管整个学院（账号管理、班级管理、学院任务、名册）。
- **院长分两种**：① **兼班主任院长**（院长 + 本班班主任 → 同班主任权限 + 学院权限）；
  ② **纯院长**（`dean_only=1`，只管学院事务，看不到班级账目/任务/成员入口）。
- **权限由后端强制**：`_STAFF_ROUTES` 角色路由表 + 端点级 `require_role` 双闸，
  前端路由守卫只负责隐藏入口，**不构成安全边界**。
- **归属权**：改 / 删 / 作废 / 关闭只能操作**自己创建**的数据。
- 班级信息里的「班主任」是 `cls_class.head_teacher` 独立字段（填姓名），与角色无关。
- **访客**（`GUEST`）可见范围由班主任逐项指定（仪表盘/账本/学生信息/任务四项，
  存在 `sys_user.guest_scopes`），后端逐项拦截，不勾 = 一律拒绝。
- **缴费对象**：除班主任外的全部学生（含生活委员与班长——他们是在班里承担班务的学生，
  班费照交；口径见 `batch_service.PAYABLE_ROLES`）。

## 二、账号体系

**没有注册页，只有登录页。** 账号不写死在代码里，也**没有默认口令**。

### 账号来源

| 来源 | 账号 | 密码 | 角色 |
|------|------|------|------|
| **部署配置声明** | `CLASSFEE_TEACHER_USERNAME` | `CLASSFEE_TEACHER_PASSWORD` | 班主任（默认）/ 生活委员 |
| 运营在页面创建 | 「成员管理 → 新增成员」时指定 | 运营设定 | 四档任选 |
| 院长在学院页创建 | 「学院 → 院长账号 → 新增」 | 运营设定 | 院长 / 院长+班主任 |

### 常用环境变量

```bash
cp .env.example .env        # 编辑；docker compose 会自动读取仓库根目录的 .env

# 手动部署时等价的环境变量
CLASSFEE_TEACHER_USERNAME=test              # 必填（与 PASSWORD 同时）
CLASSFEE_TEACHER_PASSWORD=换成强口令          # 必填
CLASSFEE_TEACHER_NAME=测试班主任              # 可选，默认同用户名
CLASSFEE_TEACHER_ROLE=TEACHER                # 可选，ADMIN | TEACHER | DEAN
CLASSFEE_DEAN_ONLY=0                         # 仅 ROLE=DEAN 时有意义：0=院长兼班主任（默认） 1=纯院长
CLASSFEE_COLLEGE_NAME=智能汽车学院            # 可选，侧栏顶部显示的学院名
CLASSFEE_JWT_SECRET=<openssl rand -hex 32>   # 令牌签名密钥，生产必填
```

> ⚠️ **`.env` 不会自动进环境变量**：`run.py` 只读 `CLASSFEE_COLLEGE_NAME`；
> 数据库账号 / JWT 密钥 / 种子班主任都要注入进程环境（systemd 里写
> `Environment=` 或 `EnvironmentFile=`），否则库连不上或空库不建 `test` 账号。

### 账号特性

- **仅首次创建**：账号已存在则跳过，**不覆盖**库里改过的密码 / 角色 / 停用状态。
- **半配置不建号**：用户名与密码必须同时填写；两项都为空则不创建任何账号。
- **纯院长**（`CLASSFEE_DEAN_ONLY=1`）：只管学院，看不到班级的账目 / 任务 / 成员入口。
- **可管理**：改资料 / 学号、重置密码、停用（保历史、禁登录）、删除（**仅限零引用**账号——
  有流水 / 缴费 / 公告 / 批次记录一律拒绝并引导改用停用）。
- **停用即时生效**：中间件每次请求都查 `sys_user.status`，被停用的账号
  **已签发的 JWT 立即失效**。
- **学号**：与登录名分开填，**同班唯一**，留空默认取登录名。
- **登录名**：全局唯一，可由本人在「个人信息」页自助修改（不分班级）。
- **改密**：本人改密走「个人信息」页（需旧密码）；运营重置他人密码走成员管理。

## 三、跨班数据怎么拿到

学生名册（学籍字段与取值）默认只对该班运营开放。**其他班的数据**按「申请 → 授权」走：

- 班主任在「学生信息 → 申请授权」提交用途，院长批准后开放只读；
- 同样的闸门适用于学生名册导出与字段维护——申请到的是**只读**，
  不是任何写入权限；
- 任何越权尝试都在后端拦截（`require_role` / 授权校验），界面隐藏只是第一道。

## 四、权限判定的代码位置（排查用）

| 想知道 | 看哪 |
|--------|------|
| 某条路由是谁能用 | `server-py/app/security.py` 的 `_STAFF_ROUTES`（中间件）与端点级 `require_role` |
| 角色等级 / 院长 / 访客判定 | `security.py` 的 `ROLE_LEVEL`、`DEAN_ROLE`、`GUEST_SCOPE_KEYS` |
| 学院名册/学生/名单授权 | `student_service.py` / `college_service.py`（`student_access_*` 表） |
| 班主任席位判定 | `college_service._adviser_role_condition()`（班主任 + 兼班主任院长） |
