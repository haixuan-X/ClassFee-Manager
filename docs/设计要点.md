# 学生信息管理系统 · 设计要点

> 产品定位与快速开始见根目录 [README.md](../README.md)；
> 功能模块与账号权限见 [账号权限.md](账号权限.md)；部署见 [部署-Linux.md](部署-Linux.md)。
> 本页讲「为什么这么设计」和必须遵守的口径。

---

## 一、核心口径（钱）

- **单一事实源**：收支共用一张 `fee_record` 流水表。**记错优先走「作废（红冲）」留痕**，运营也可物理删除（事务内回滚余额并联动缴费状态），列表默认隐藏已作废。
- **审计留痕**：作废 / 关闭 / 编辑都会记下**谁**在**什么时候**动的
  （`voided_by`、`closed_by`、`updated_by`），界面可见「由 X 于 … 作废」。
  删除仍是硬删无痕——留痕路径是「作废 / 下架」，界面文案一律引导「记错优先作废」。
- **余额**：`SUM(收入 NORMAL) − SUM(支出 NORMAL)`，`cls_class.balance` 作冗余列
  在**同一事务内原子 UPDATE**，不接受手改；可与流水对账。
- **金额**：数据库 `DECIMAL(10,2)`，Python 侧 `Decimal` + `HALF_UP` 量化，**全链路禁止 float**。
- **缴费单一入口**：成员缴费在「收费批次 → 标记缴费」一个事务写入
  （`fee_record` + `fee_payment.status` + 余额），杜绝第二条资金写入路径。

## 二、小票

- 支出可挂票据（`POST /api/files` 上传 → `receiptUrl` 挂账 → 账本点「查看」带 token 取图），**仅支出可挂**。
- 前端选图**自动压缩**（最长边 1600px / JPEG q0.8）再上传——手机原图（3–9MB）
  直接顶共享 axios 10s 超时必超时（「网络异常 / timeout of 10000ms exceeded」）。
- 服务端：≤5MB、魔数嗅探（拒绝伪装扩展名）、uuid 命名落 `uploads/receipts/`、
  仅本班流水引用才放行读取，删流水时回收未被引用的文件。

## 三、任务口径

- 题型 `BOOLEAN / SINGLE / MULTI / DATE`；**发布时只开放「是/否」「单选」**（`MULTI/DATE` 仅编辑旧任务可见）。
- **候选项上限 4**（`task_service.MAX_OPTIONS`，前端 `TaskPublishDialog` 同值），只挡新建。
- **明细看板按题型分流**：是/否/日期 → 返校四桶；单选/多选 → 按选项
  （零人选项也列出 + 未填），两种口径共用一套筛选 / 导出。
- 学院任务 `canAnswer` 恒 false（院长自己不填），「填写」按钮由 `canFill` 控制。
- **学院任务回收率** = 学生**全部点完名**的班数 / 分母 = 已登记班主任的班数
  （`_adviser_role_condition()` 共用一份判定），别再拿全班人数当分母。
- **班级任务**按班主任统计回收进度（人），单位文案 `COLLEGE → 班`，其余 `→ 人`
  （前端 `utils/taskStatus.ts`，后端不重写关键词表）。
- 学籍变化（仪表盘 `changeTotal`）= **当前不在籍人数**（毕业/入伍/休学/退学/其它），
  没有历史表，给不了「本学期异动人次」——别再当时间口径用。

## 四、权限与学院口径接口

- **权限判定全链路看 `ROLE_LEVEL`**（`MEMBER=0 / GUEST=0 / ADMIN=1 / MONITOR=2 / TEACHER=3 / DEAN=4`），不写 `role == "TEACHER"`。
- 后端双闸：`_STAFF_ROUTES` 角色路由表（中间件）+ 端点级 `require_role`，
  前端路由守卫只隐藏入口、**不是安全边界**。
- **学院口径接口不带 `classId`**：`web/src/api/request.ts` 的 `skipClassId` 名单
  （`/college/`、`/dashboard/students`、`/tasks/overview`）。**新增学院口径接口必须加进去**，
  否则会被塞「当前班」——学院任务/总览会莫名其妙变成 0 条。
- 归属权：改 / 删 / 作废 / 关闭只能操作**自己创建**的数据（班主任也动不了别人的）。

---

## 五、界面与无障碍

- 浅色玻璃拟态；**收入 `+¥` 绿、支出 `−¥` 红，但符号优先于颜色**，不靠颜色单独传达信息。
- 正文对比度 ≥4.5:1；弹层三条关闭路径（Esc / × / 遮罩）；`prefers-reduced-motion` 降级；
  图表带 `role="img"` 与动态 `aria-label`；侧栏用原生 `<a>`（可 Tab、可中键新开标签）。

## 六、数据模型（15 张表）

`schema.sql` 由后端启动时**幂等执行**；改列定义时**必须**同步两处：

1. `server-py/db/schema.sql`（新库）
2. `server-py/app/seed.py` 的幂等 `ALTER`（既有库）

| 表 | 用途 |
|----|------|
| `cls_class` | 班级（含冗余余额列、`head_teacher` 纯文本） |
| `sys_user` / `sys_user_class` | 用户 + 多对多班级关联（`is_adviser=1` = 班主任） |
| `fee_category` | 收支类别字典（启动时按 kind 幂等补齐 11 条） |
| `fee_record` | **核心流水**，作废 = 红冲，审计列 `voided_by/voided_at` |
| `fee_batch` / `fee_payment` | 收费批次 + 逐人缴费状态 |
| `sys_notice` | 班级公告，审计列 `updated_by/updated_at` |
| `student_field` / `student_record` / `student_record_value` | 学籍名册字段设计 + 逐人取值 |
| `student_access_request` / `student_grant` | 跨班数据访问申请与授权 |
| `cls_task` / `cls_task_answer` / `cls_task_student_answer` | 任务 + 本人答案 + 院长视角学生级答案 |
